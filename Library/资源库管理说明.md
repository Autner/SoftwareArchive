# 个人软件资源库管理说明（macOS 版）

本文档用于长期记录 SoftwareArchive 的目录规则、入库流程、更新流程、失败恢复和云端备份方法。本版本针对 macOS（bash 实现）。

当前版本：见仓库根目录 VERSION.txt 与 CHANGELOG.md

## 1. 目录结构

```text
SoftwareArchive/
├── README_先读我.md
├── 启动软件档案管理.command
├── Library/
│   ├── 资源库管理说明.md
│   ├── 资源索引.xlsx
│   └── 软件名/
│       ├── info.yml
│       ├── 使用手册.md
│       ├── checksums.sha256
│       ├── Packages/
│       ├── Source/                 # Maintain 使用
│       ├── Docs/
│       └── Archive/
│           ├── Packages/
│           ├── Source/
│           └── Docs/
└── Work/
    ├── Scripts/
    │   ├── SoftwareArchive.sh
    │   ├── SoftwareArchiveCore.sh
    │   └── Init.sh
    ├── Config/
    │   └── config.yml
    ├── Repositories/
    ├── Downloads/
    └── Temp/
```

目录职责：

- `Library`：正式、长期保存的资源。
- `Work/Scripts`：管理脚本（bash）。
- `Work/Config`：全局配置。
- `Work/Repositories`：Maintain 软件的 Git mirror，可从 `Source/*.bundle` 或远程仓库重建。
- `Work/Downloads`：临时下载区，可清理。
- `Work/Temp`：入库和更新的暂存任务区，可恢复。

## 2. 软件信息规则

每个软件使用一个 `info.yml`：

```yaml
name: "SoftwareA"

platforms:
  - "Windows"
  - "macOS"

update_policy: "Maintain"

current_version: "v2.5.0"

source_url: "https://github.com/owner/project"
source_type: "GitHub"

tags:
  - "文件管理"
  - "效率工具"

license: "MIT"

last_checked: "2026-08-29"

notes: ""
```

字段约束：

| 字段 | 规则 |
|---|---|
| `name` | 必填，且必须能作为文件名（含 Windows 禁用字符与保留名，保证跨平台兼容） |
| `platforms` | 必填，至少一个 |
| `update_policy` | 必填，只允许 `Fixed` 或 `Maintain` |
| `source_url` | Maintain 必填；Fixed 可空 |
| `current_version` | 可空；Fixed 版本目录使用 `Unknown` |
| `source_type` | 脚本根据常见网址自动判断 |
| `tags` | 可空，可多项 |
| `license` | 可空 |
| `last_checked` | 脚本维护，格式为 `YYYY-MM-DD` |
| `notes` | 可空 |

`info.yml` 是软件信息的唯一数据源。需要修改信息时，先修改 `info.yml`，然后在主菜单重建资源索引。


### 软件生命周期状态（status）

`info.yml` 支持可选的 `status` 字段，取值：

- `active`（默认）：正常使用，参与「检查全部更新」
- `deprecated`：已失效/停止维护（如上游被下架、修改版失效），不参与更新检查
- `migrated`：已迁移到其他软件，仅作历史记录

在主菜单「标记软件状态」中设置；主菜单顶栏会显示非 active 的数量。

## 3. Fixed 新软件入库

```text
主菜单选择「收录新软件」
→ 选择 Fixed
→ 填写名称并多选平台
→ 可选填写版本、标签、许可证和备注
→ 系统文件选择器选择安装包（可多选）
→ 逐个确认安装包平台
→ 在 Work/Temp 创建暂存任务
→ 复制到 Packages/版本或 Unknown/平台/
→ 生成 info.yml
→ 生成 checksums.sha256
→ 生成 使用手册.md
→ 暂停，用户手动完善使用手册
→ 用户确认「我已完成使用手册」
→ 提交到 Library
→ 重建 资源索引.xlsx
→ 显示阿里云盘上传清单
```

Fixed 软件必须选择至少一个本地安装包。未知版本统一使用 `Packages/Unknown/`。

## 4. Maintain 新软件入库

```text
主菜单选择「收录新软件」
→ 选择 Maintain
→ 填写名称、平台和 source_url
→ 自动识别 GitHub、GitLab 或 Other
→ 查询最新正式 Release
→ 用户确认是否采用该版本
→ 从 Release Assets 列表选择一个文件
→ 为该文件指定平台并返回文件列表
→ 重复处理其他文件，选择「完成安装包选择并继续」
→ 下载到 Packages/版本/平台/
→ 建立 Work/Repositories/软件名.git mirror
→ 生成 Source/软件名.bundle
→ 生成 info.yml 与 checksums.sha256
→ 生成 使用手册.md
→ 暂停，用户手动完善使用手册
→ 用户确认「我已完成使用手册」
→ 提交到 Library 并重建索引
```

未发现正式 Release 时可选择：仅归档源码；手动选择安装包；取消入库。

查询失败（网络错误、API 限额）会进入独立菜单：重试查询、仅归档源码、手动选择安装包、取消入库。

Maintain 软件允许 `Packages` 为空。`Source/软件名.bundle` 必须完整生成。

## 5. Fixed 软件更新

```text
主菜单选择「更新已有软件」
→ TUI 选择 Fixed 软件
→ 填写新版本号，可留空
→ 选择新安装包并确认平台
→ 选择旧版本处理方式
   - 保留在 Packages
   - 移动到 Archive/Packages
   - 从本次正式结果中删除
→ 更新 info.yml 与 checksums.sha256
→ 检查 使用手册.md
→ 确认已修改或无需修改
→ 提交并重建索引
```

删除旧版本发生在暂存副本中。正式库在最终提交前保持原状态。

## 6. Maintain 软件更新

```text
主菜单选择「更新已有软件」
→ TUI 选择 Maintain 软件
→ 查询并显示当前保存版本、最新 Release 和发布时间
→ 选择「更新 Release 安装包与源码」或「只更新源码 bundle」
→ 逐个选择 Release Asset 并指定对应平台
→ 回到文件列表继续处理，最后明确选择完成
→ 人工选择旧版本处理方式
→ 更新 Git mirror
→ 生成新的完整 bundle
→ 更新 info.yml 与 checksums.sha256
→ 强制进入使用手册检查环节
→ 确认已修改或无需修改
→ 提交并重建索引
```

选择了「更新 Release」但没有映射任何文件时，按「只更新源码 bundle」处理，不会改动版本号与旧包。

每次 Maintain 更新都要经过使用手册检查。功能或操作变化时应同步修改手册，小型修复可选择「本次检查后无需修改」。

## 7. 更新策略转换

### Fixed 转 Maintain

1. 选择「修改更新策略」。
2. 填写并校验 `source_url`。
3. 创建 `Source`。
4. 建立 Git mirror 并生成完整 bundle。
5. 更新 `info.yml`、校验文件和资源索引。
6. 检查使用手册。

现有 `Packages`、`Docs`、`Archive` 与使用手册全部保留。

### Maintain 转 Fixed

1. 更新 `update_policy` 为 `Fixed`。
2. 后续停止 Release 自动查询。
3. 保留已有 `Source/*.bundle` 和仓库来源信息。
4. 更新校验文件和资源索引。
5. 检查使用手册。

## 8. 删除软件

主菜单「删除已有软件」用于彻底移除一个软件的全部本地数据：

1. 选择软件，页面显示删除范围与大小；
2. 删除范围包括 `Library/软件名`、`Work/Repositories/软件名.git`（如存在）和该软件在 `Work/Temp` 中的未完成任务；
3. 手动输入软件名称二次确认（区分大小写，`Esc` 取消）；
4. 删除完成后按剩余软件重建 资源索引.xlsx。

删除不可恢复，脚本不联动云端。删除完成后请同步删除阿里云盘上的对应软件目录，并上传新的资源索引.xlsx。`info.yml` 损坏的条目同样可以删除（列表中策略显示为 Invalid）。

## 9. 使用手册规则

软件根目录统一使用 `使用手册.md`，基础结构包括：

1. 软件简介；
2. 主要功能；
3. 安装与启动；
4. 基本使用；
5. 常用功能；
6. 注意事项；
7. 当前推荐版本。

新软件入库时，脚本生成基础文件后暂停。用户必须手动完成说明内容，并回到脚本确认「我已完成使用手册」。可以选择「暂存任务并退出」，下次启动时继续。

已有软件更新时，脚本同样暂停检查手册。用户可以确认已经修改，也可以确认本次无需修改。

## 10. Docs 使用规则

`Docs` 可以保存：

- 官方 README；
- LICENSE、NOTICE；
- 官方安装、配置和开发说明；
- 重要 FAQ；
- 项目 Wiki 的关键内容；
- 后续维护源码可能需要的技术资料。

`Docs` 允许为空。安装包归入 `Packages`，源码归档归入 `Source`，个人使用说明归入根目录的 `使用手册.md`。

## 11. Archive 使用规则

- `Archive/Packages`：有兼容性、稳定性或历史价值的旧安装包。
- `Archive/Source`：明确需要长期保留的历史源码 bundle。
- `Archive/Docs`：旧版且仍有参考价值的文档。
- Archive 内容由用户决定，脚本不进行自动淘汰。
- 没有保留价值的旧内容可在更新向导中删除。

## 12. SHA256 与完整性校验

每个软件只维护一个 `checksums.sha256`，校验范围包括：

```text
Packages/**
Source/**
Archive/Packages/**
Archive/Source/**
```

`info.yml`、`使用手册.md` 和 `Docs` 不进入校验范围。入库、更新和策略转换完成时会重新生成校验文件。

主菜单「校验资源完整性」会报告：

- `OK`：哈希一致；
- `Missing`：文件缺失；
- `Mismatch`：文件内容变化或损坏；
- `Unlisted`：校验范围内存在尚未登记的文件；
- `Invalid`：校验文件中的行格式无效。

## 13. 资源索引（TSV + XLSX）

重建索引时同时生成两个文件：

- `资源索引.tsv`：纯 bash 生成、无 zip 依赖、制表符分隔（机器可读）；`-Action List` 可直接输出到 stdout
- `资源索引.xlsx`：如下的可读表格；生成失败时只提示、不阻断（TSV 已可用）

### xlsx 字段

索引固定包含以下字段：

| 列 | 来源 |
|---|---|
| 名称 | `name` |
| 标签 | `tags`，使用 `/` 合并 |
| 平台 | `platforms`，使用 `/` 合并 |
| 当前保存版本 | `current_version` |
| 来源类型 | `source_type` |
| 来源地址 | `source_url`，可点击链接 |
| 更新策略 | `update_policy` |
| 最后检查 | `last_checked` |
| 备注 | `notes` |

生成规则：扫描 `Library/*/info.yml`，按名称排序，冻结首行，启用自动筛选，并设置适合阅读的列宽。索引由脚本手工构建 OOXML 并用系统自带 zip 打包，不依赖 Excel 或任何第三方库。

## 14. TUI 与输入容错

- 菜单使用方向键、Space、Enter 和 Esc。
- 软件支持平台使用多选界面。
- Release Assets 使用逐文件映射界面：选一个文件、指定平台、返回列表，再处理下一个文件。
- 本地文件使用 macOS 系统文件选择器（多选）；无法弹出时自动退回路径输入。
- 名称、URL、版本、许可证和备注需要键盘输入，支持中文等 UTF-8 文本。
- 每个文本输入界面都会显示示例；按 `←`、`→` 可在现有文字中移动光标，按 `Backspace` 或 `Delete` 修改，按 `Ctrl+U` 清空，按 `Esc` 返回上一步，按 Enter 确认输入。
- 入库向导使用步骤状态保存已填写的名称、平台与来源地址，返回时不会直接跳到主菜单。
- 标签输入会实时回显已录入内容，单个标签限 40 个字符。
- 必填项为空、URL 无效、名称含禁用字符时会提示并重新输入。
- 重要操作会先显示汇总或二次确认；彻底删除需输入软件名称。
- 输入错误和网络错误会保留任务状态并返回安全界面。

## 15. 任务暂存、失败恢复与提交

入库和更新先在以下位置完成：

```text
Work/Temp/时间戳_软件名_随机串/
├── task.json                  # 任务元数据
├── context-info.properties    # 恢复用：软件信息
├── context-release.properties # 恢复用：Release 与资产（下载阶段）
├── context-mappings.tsv       # 恢复用：文件与平台映射（下载阶段）
└── Staging/                   # 暂存目录
```

正式提交顺序：

1. 检查暂存区的 `info.yml` 与 `使用手册.md`；
2. 重新生成 SHA256；
3. 将旧正式目录移动到任务备份区；
4. 将暂存目录移动到 `Library/软件名`；
5. 重建资源索引；
6. 成功后清理旧目录和任务。

目录改名失败（例如文件被其他程序打开）时自动降级为复制+删除；提交失败会回滚正式软件目录。

下次启动主脚本会列出未完成任务。达到安全检查点的任务提供：继续；打开任务目录；删除任务并重新开始；稍后处理。`ReleaseDownloadPending`、`GitArchivePending`、`ManualPending`、`ManualConfirmed` 均可安全恢复。

安装包下载支持断点续传：下载中断后 `.partial` 断点文件会保留，重试时从已下载位置继续，网络短暂中断会自动重连（最多重试 10 次）；已完整下载的文件按名称和大小跳过，不会重复下载。

Git mirror 首次克隆会先写入 `.partial` 目录，成功后才提交为正式 mirror。git 与下载在未单独配置代理时会自动使用 macOS 系统代理（网络设置中的手动 HTTPS 代理）。

临时目录自动清理会跳过所有未完成任务。

## 16. 阿里云盘备份流程

长期保存：

```text
SoftwareArchive/
├── Library/
└── Work/
    ├── Scripts/
    └── Config/
```

每次软件入库或更新完成后：

1. 删除云端同名旧软件目录；
2. 上传本地 `Library/软件名/` 完整目录；
3. 上传新的 `Library/资源索引.xlsx`。

`Repositories`、`Downloads` 和 `Temp` 可重建，无需上传。

## 17. 环境恢复

1. 从阿里云盘下载 `Library`、`Work/Scripts` 和 `Work/Config`。
2. 保持三者在同一个 `SoftwareArchive` 根目录。
3. 运行 `bash Work/Scripts/Init.sh`，或双击启动文件后在主菜单选择「重新初始化工作环境」。
4. 脚本会补建 `Repositories`、`Downloads` 和 `Temp`。
5. Maintain 仓库可从远程仓库重新 mirror；断网恢复时也可以使用 `Source/*.bundle` 手动重建（`git clone Source/软件名.bundle`）。

## 18. 凭据与 API 限额

公开仓库无需令牌。脚本默认调用 GitHub `/releases/latest` 获取最新正式版本。Release 的 JSON 解析使用 macOS 自带的 osascript（JXA），无需安装任何依赖。

遇到 API 频率限制或私有仓库时，可在启动脚本前设置环境变量：

```bash
launchctl setenv GITHUB_TOKEN 你的令牌    # 之后重新打开终端生效
launchctl setenv GITLAB_TOKEN 你的令牌
# 或临时：export GITHUB_TOKEN=你的令牌 后再运行脚本
```

令牌不会写入 `config.yml`、`info.yml` 或任务文件。

## 19. 主脚本入口

日常使用：双击 `启动软件档案管理.command`（首次需先运行一次 `bash Work/Scripts/Init.sh` 设置执行权限）。

命令行入口：

```bash
# 打开主菜单
bash Work/Scripts/SoftwareArchive.sh

# 初始化目录并重建空索引或现有索引
bash Work/Scripts/Init.sh

# 只重建索引
bash Work/Scripts/SoftwareArchive.sh -Action RebuildIndex

# 非交互校验全部软件（含源码 bundle 的 git bundle verify）；发现问题时退出码为 2
bash Work/Scripts/SoftwareArchive.sh -Action Verify

# 输出 TSV 软件清单到 stdout（供其他工具消费）
bash Work/Scripts/SoftwareArchive.sh -Action List
```

### v1.0.9 新增功能速览

- 「检查全部更新」：批量查询所有 Maintain + active 软件的最新 Release
- 「搜索档案」：关键字匹配名称/备注/标签/状态/手册全文
- 「标记软件状态」：active / deprecated / migrated
- 「维护源码镜像 (Maintain)」：独立入口，直接更新 Git mirror 与 bundle
- 「导出 / 导入软件条目」：`.saentry.zip` 分享与入库
- 并发锁：两个实例不能同时进入菜单或批量写操作；持锁进程异常退出后自动回收
- 单元测试：`bash Work/Tests/run-tests.sh`（CI 同步执行）

## 20. 关键规则速查

- `info.yml` 是软件信息唯一数据源。
- Excel 索引由 `info.yml` 自动生成。
- Maintain 默认忽略 Draft 与 Pre-release。
- 首次入库必须手动完成使用手册。
- 每次软件更新必须检查使用手册。
- 正式资源只存放在 `Library`。
- 安装包、bundle 和归档二进制文件使用 SHA256。
- 入库与更新先写入 `Work/Temp`，完整成功后提交。
- 未完成任务不会被临时清理程序删除。
- 阿里云盘保存 `Library`、`Work/Scripts` 和 `Work/Config`。
- 更新完成后，云端同名软件使用本地完整目录替换。
- 「删除已有软件」会移除该软件的 Library 目录、Git mirror 和未完成任务并重建索引，需输入软件名确认，不可恢复。
